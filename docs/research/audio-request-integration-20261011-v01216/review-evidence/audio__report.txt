review_design.py independently opens the original EXE as read-only, verifies

Their combined signature extent is 1,520 bytes.

The independent scalar review checks access widths and direct positive
references to AD9390 (signed DWORD), AD93C0 (byte), AD93C4 (signed DWORD).
The three reservers compare inhibit against zero, free against 16 with JLE,
and interval against 24 with JG. All 4,212 bounded tuples agree with those
native branch predicates. The final count is recorded in design-review.json;
the initial phase passed 13,153 checks before the extra snapshot manifest pins.

00DA30 initializes free capacity to 80. 1DD8D0 returns an index and increments
free during retirement, then resets the interval at the end of the pass.
Independent evaluation of 00DA30's SIMD constant loads/stores additionally
confirms all 80 initial free indices are exactly 0 through 79, covering the
320-byte free-index table. Its record loop count is 80 and stride is 56.
1DE7C0 resets interval and inhibit, but does not restore free capacity to 80.
These fields therefore do not count audible voices, reliably record transient
requests or establish a rate. The accepted free range 0-80 is a scalar bound,
not proof that the native pool is structurally consistent.

Native implementation and production route
-----------------------------------------
The new helper reads exactly nine state bytes per copy: four, one, four.
It separately reads 1,520 bytes for the eight code signatures. It does not
walk request lists, pool entries, resource/bank/Actor/camera objects or invoke
audio code, DecodePacked or the sound critical section. No game write, new
thread, scheduler hook or protocol expansion is added.

Code review confirms base/context, bound game thread, disabled state, IPC
mapping and fresh host checks; no scene dependency. Each tuple uses signed
free 0-80, signed interval 0-25 and canonical inhibit 0/1. Both copies must
validate and compare equal before any of the three values is published.
The limits mask uses the same copied fields. A final context/host check is
performed. TrainerFrame clears old values and validity before sampling and
publishes under the existing snapshot sequence. Read-only commands 1482-1484
are claimed explicitly before the generic progression fallback.

The four new integration points in TrainerBridge.cpp are its include,
handler dispatch, capabilities and snapshot invocation. Existing UpdateHook
calls OnFrame after the original Update returns; OnFrame requires successful
result, the active App and the bound game thread before TrainerFrame runs.

Reviewer-owned production_route_review.cpp includes the real TrainerBridge.cpp
without any test defines or replaced Windows APIs. Its synthetic module is
non-executable, and it is PAGE_READONLY during every observed call. Thus an
attempt to execute original game code or write to that module would fault.
The fixture runs all bounded tuples, all invalid inhibit bytes, signed edge
values, signature corruption, actual inaccessible pages, base/host/thread
guards, and 15 actual TrainerFrame calls. It checks all eight mask cases,
capabilities, scene independence, 1482-1484 rejection, previous-value clearing,
host expiry and OnFrame early App/thread/result/disabled rejection.
Result: 22,380 checks, zero failures; no game or visible UI access.

The author's targeted AudioRequestGuardTests were separately rebuilt and
rerun in this review directory: 21,097 checks, zero failures. This runner also
compiled the production TrainerBridge.cpp with no test defines. Its isolated

Limits
------
- Equal scalar copies are not an atomic snapshot, lock or ABA detector.
  Intermediate mutations and changes immediately after sampling can be missed.
- Positive selected xrefs and ten bodies do not close indirect/alias writers,
  every consumer or global pool ownership/lifetime/thread ordering.
- No selected game instructions, real game process, attach, injection, native
  audio call, original-file write, save or GUI operation was performed.
- Successful OnFrame UI/key processing and the real Update call were not
  executed. Their routing was reviewed; synthetic TrainerFrame and its helper
  were executed directly. Early OnFrame rejection paths were executed.
- The managed fixture tests actual linked source logic. The final packaged
  trainer assembly, visual layout and live behavior require separate checks.
- This review applies to the file hashes in review.json, not later edits.
