Vector ABI and edge cases

0:13 rotates around Y;0:68 around X. Their angle argument is visible in XMM2 at the helper call although the decompiler's call expression omits it.0:83 receives its angle in XMM3 and normalizes a copied axis. Their return buffers are shared and can be overwritten by later native calls.

0:46 passes operand2 in XMM3.3B7200 normalizes local direction copies, computes their angle and cross-product axis, multiplies the supplied rate by global717480, then follows COMISS/JA and MAXSS. For finite nonnegative rate*tickFactor it uses min(angle,step). There is no special antiparallel-axis fallback: a zero axis can produce cos(angle)*I, so partial turns can shorten the direction. NaN sanitization happens in the referenced input memory before local copies are made.

0:54 composes X, Y and Z rotations and transforms (0,0,1,0). Its repeated-add/subtract wrapper1A90C0 can fail to progress for infinities and sufficiently large finite floats; the verifier shows the IEEE-float stall for +/-infinity and +/-2^28. This is distinct from the fmodf wrapper used by13/68/83.

0:90 declares five operands but reads only a vector address and a scalar. It constructs a matrix entirely in its stack frame, stores the sanitized vector in the translation column and discards the matrix. It has no VM return and no drawing/publication call. Input NaN cleanup still has an externally visible write. This is not a pure no-op.
