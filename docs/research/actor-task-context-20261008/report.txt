Task normal completion
  Sites: 0x14014F659, 0x14014F67B
  The task callback has returned and 14F650 removes its frame before the parent switch; the OS trampoline stack still exists until deletion.
  Parent observes null callback, retires the fiber and removes the task.

Task cancelled while parked
  Sites: 0x140150180, 0x1401354E0, 0x1401351ED
  An abandoned callback stack can remain allocated in the deferred-deletion queue after task/context storage is removed.
  Deletion discards the fiber stack without a native guarantee of resumption and normal callback return. A wrapper exit counter alone is insufficient.

Microsoft's SwitchToFiber contract describes the saved/restored execution state; DeleteFiber releases the fiber's stack. Combining those contracts with the queue/destructor code establishes that native cancellation does not guarantee resumption and normal return of the cancelled callback. This final point is a code/API inference.

THREAD AND WORKER BOUNDARY
- Direct tasks execute on the invoking scheduler's current stack. Fiber tasks execute on the Windows thread which schedules the fiber. The normal nested path is therefore concrete, but it is not a universal ownership proof.
- The captured switching code uses globals 713420, 8BBCF8, 713430/713438 and 713440 rather than a visible TLS lookup. No thread-ID gate or lock is visible in 135470; the absence of a local gate cannot establish an external invariant.
- App update 14EB70 has original vtable/data references, including 5B11B0. The final outer virtual dispatch and its OS-thread owner remain unresolved in this bounded set.
- 152990 has 25 incoming xref occurrences: 23 code sites, its own RUNTIME_FUNCTION.BeginAddress entry, and the preceding RUNTIME_FUNCTION.EndAddress reference. Source sites are verified; their complete caller chains and thread identities are not captured here.
- Existing worker research demonstrates six motion worker dispatch/join paths and a separate resource worker, plus a possible worker-to-BDX route. This set does not identify an actual shipped event/asset that reaches these transition/task mutations from a worker, and does not exclude one.
- Microsoft permits suitably synchronized fibers to be switched by a different thread. The use of CreateFiber/SwitchToFiber alone is not evidence against migration or concurrency.
- Task cleanup slot +104, manager allocation/free virtual slots, other scheduler callers, and transitive actor/heap callees remain dynamic or outside this capture. No full no-yield or no-worker closure is claimed.

ERROR AND ABORT PATHS
Allocation and API preconditions
  14F8A0 and 14F770 use allocator results without local null recovery. 135250 returns null when its object allocator returns null, and stores a failed CreateFiber result without checking it; 14FD60/135470 do not locally recover. ConvertThreadToFiber's result is likewise stored without a local failure branch.
  Boundary: Static missing checks, not induced or observed failures; allocator semantics and system resource conditions were not tested.

Deferred retirement is not idempotent
  1352E0 checks only next==0, not its +40 marked flag. Requeueing the current tail makes next point to itself. 135470 reads that next before destructing the queued object, so this input violates the queue's one-retirement-per-object precondition.
  Boundary: The shown callers clear their fiber pointer. No reachable duplicate-retirement bug in an unmodified playthrough is claimed.

Cancellation skips normal callback completion
  Cleanup callbacks execute from the canceller. Task/context are removed, then deferred DeleteFiber releases the suspended stack. No normal return path is supplied for the cancelled callback.
  Boundary: The claim is about this native mechanism and the API stack-deletion contract; transitive custom cleanup callbacks may perform additional work.

Unexpected fiber callback return
  135220 enters an unconditional self-loop after its callback returns. Normal 14F650 completion tail-switches away instead.
  Boundary: This is a fallback behavior, not an observed hang.

Transition deferral
  152A90 decrements task+24 and returns while positive, or returns when 1515C0/19BA60 report busy. Its destructive section is reached only after those branches; direct registration 152990 is therefore not itself the whole teardown boundary.
  Boundary: Readiness helper semantics and every side effect were not exhaustively re-proven.

PRACTICAL USES
- Explain Field loading, unloading and task timing with concrete scheduler identities and continuation addresses.
- Build a read-only task/fiber diagnostic model with states registered, active, parked, retired and deleted; include the module parent relationship and deferred deletion list.
- Design future lifetime instrumentation around explicit task admission, suspension, cancellation and deletion events, with durable metadata independent of task storage.
- Keep any future Actor/STATUS write provider gated until outer dispatch ownership, worker entry paths, binding stores and heap invalidation have a compatible proven serialization contract.
