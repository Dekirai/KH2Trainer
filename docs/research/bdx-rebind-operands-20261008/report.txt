Result
======
The missing wrapper construction is present in both original scripts. The native
Actor setup passes one tagged encoded Actor pointer to Event0. The script moves
that value into its initial frame, passes it together with a Work-region pointer
through real nested calls, and stores the Actor into wrapper+4. The later rebind
trap receives that wrapper. This closes the static operand chain under the normal
execution and storage assumptions below; it is not a live execution observation.

Native setup and storage
========================
3B44D0 skips setup when Actor flags+1736 has bit0x20, otherwise selects first
BAR type3 via3A6420. Both original BAR files contain exactly one such entry.
After successful native resource decoding/context allocation, the caller places
Encode32(Actor) and tag @ADR in one eight-byte argument, calls3E1840 with ID0 and
count1, then selects entry1. The temporary Event0 context shares the persistent
context's work and owner through3E1240. 41B320 creates four initial DWORDs,
advances the frame by16 and copies the one tagged argument onto the operand stack.
3E1C80 invokes41B400 with the native bank root and a NULL opcode-trace callback.
41C900/41C6C0/41C780 supply the frame/work address and tag-preserving load/store
semantics; the symbolic model represents their decoded pointer identity rather
than concrete addresses, actual allocation, or all possible VM tag behavior.

It does not treat a syntactic call-continuation edge as evidence that the call did
nothing. For AL020, all256 possible byte values returned by1:23 were checked:

Conditions and limits
=====================
Valid, distinct Actor/work/frame/temp storage; successful allocations; live BAR
and strings; normal pointer encode/decode round-trips; stable scripts/native bank
tables; no concurrent or reentrant mutation; normal returns from native calls.
The native runtime float compatibility adjustments are not numerically emulated;
they do not choose these wrapper addresses or immediate resource IDs. Motion
field numeric results are not claimed identical to stored-byte values.
This does not establish when an actor using either asset is spawned, successful
native resource acquisition/rebind, a thread/fiber/lifetime exclusion, or Event27
reachability. A different caller of Event0 may supply another initial argument.
