MP ActiveCheck and movement ownership-policy review
===================================================

No blocking finding in the reviewed changes against v0.12.2 Source.zip. MP gauge validation, prior/current usability accounting, monitor/sustain/extension gates and visible reasons are coherent. Losing MP maximum alone does not block releasing the owned MP toggle.

Both identified movement policy gaps are closed. ReadRestorableValue validates originals using the current FeatureDefinition.IsValidValue contract before starting, and the second original is checked again after the awaited first command. During runtime, all three movement rewards also use MovementReadiness as ActiveCheck. Each restoring owned value gets an additional fresh policy check inside SustainAsync before dispatch and before saving a new Original. An out-of-policy second value appearing during an earlier awaited command is therefore preserved. Intentionally non-restoring values retain their existing behavior. Cleanup remains separate from the usefulness gate.

The actual tests cover walk100/run100/jump1200/fall0, both policy boundaries, loss/change after the first awaited write, script changes during runtime, pause/recovery accounting, valid replacement originals, external-value preservation and the second sustain-command race.
