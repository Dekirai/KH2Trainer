1. Scope and evidence
---------------------
This adds 17 proposed descriptions: 3:13..16, 44, 97..107 and 160. The
previous Bank3 study's 30 annotations remain unchanged. This is not semantic
completion of all 179 structural Bank3 rows. No product or trainer behavior
was changed here.

capture.json contains fresh read-only IDA captures from the existing adopted
worker 47255c5b. Each selected body has complete paginated ASM, primary bytes
and pseudocode. The recorded database had auto_analysis_ready=false;
autoanalysis, database writes and restarts were not requested. Function sizes
and IDA boundaries are observed metadata, then checked against the original
PE. Six long pseudocode captures retained IDA's truncated flag on their final
page; separate complete single-page responses corroborate their exact joined
text. No metadata flag is silently rewritten in the capture.

verify.py independently parses the PE, requires the full original SHA256,
compares every captured body/data span with disk bytes, decodes every listed
instruction with Capstone, checks counts/cursors, descriptors, 113 explicit
semantic anchors, RTTI, float constants, xref encodings, annotation ABI and
reference targets. evidence.json and the listings are deterministic derived
outputs. Unlisted bytes within primary bodies remain explicitly counted;
they are not counted as extra instructions. The descriptor-table data span
contains 179 rows, but only the selected 17 descriptors are semantic claims.

Reproduce from the workspace root (Python3 plus Capstone):
  py -3 -B docs/research/bdx-bank3-extended-20261008/verify.py --check
Optional --original PATH selects the PE; the SHA must still match.
Verification never loads, executes, injects or patches KH2. The PE parser and
page-verification scaffolding were adapted from the previous Bank3 study;
this verifier is self-contained and does not import or modify that study.

3. Durability and three different cached state predicates
---------------------------------------------------------
3:97 tests inclusive float32(maximum)*0.3 >= current. Current is a float at
PLAYER_STATE+8 and maximum a signed DWORD at+12.225D00 accumulates maximum,
enforces at least1 and copies it into current.225E60 subtracts signed integer
damage, selects a category and clamps nonpositive current to0. Native contact
callers use this alongside effects/feedback, supporting the bounded name
durability. The query itself has no alive/state or valid-number gate. SETNB
after COMISS makes unordered false with masked floating exceptions.

3:98 reads player flags+5132 bit2. State2 processing clears the previous bit2,
transfers pending bit1 to bit2 and clears bit1. Captured damage entry paths
set pending bit1 after their rejection checks but before durability change.
This is an update pulse, not a permanent dead/damaged predicate.

3:99 reads bit0x200, refreshed by the priority19000 task in player state2.
The source predicate traverses component head(player+1312), with encoded
next at component+1344. Type1 tests a subordinate list(+1448, next+164) for
entry+156 bit1. Type13 calls descriptor virtual+64. The exact list predicate
is documented; a universal firing/readiness name is intentionally unproven.

3:100 reads bit0x40. The state2 input update clears it, then tests controller
DWORD+8 mask0x400 while bit0x80 is clear. A successful start sets0xC0, copies
the lateral direction, configures a timed movement impulse and spin, can
start the+1500 protection timer, and invokes an effect helper. The query is
the start pulse; it is not a permanent maneuver-active or invulnerable flag.
No physical button mapping is claimed. Other state paths can retain values.

4. Counter affects ordinary movement as well as reactions
----------------------------------------------------------
3:101/102 do a DWORD INC/DEC on player+5128;3:103 returns that DWORD as INT.
There is no saturation, balancing check or atomic/thread contract. For
example DEC(0) gives0xFFFFFFFF, read as-1 by the consumer; INC(0x7FFFFFFF)
wraps to the negative half. This is unrelated to lifetime reference counts.

1FF930 interprets N as signed. N<=0 returns1 without dereferencing config.
For N>0 it sequentially computes, with float32 rounding after each operation,
  v = 1; for k=1..N: v = v - config[+16]/float32(k)
An eight-way unroll and a tail preserve that operation order. The final
COMISS/JA returns float32(0.1) if v is strictly below it, otherwise MINSS(1,v).
With masked exceptions, NaN can survive; this is not universal sanitization.
Positive work remains linear in N even once the final clamped value is clear.
A huge positive counter can consume excessive work. No such live test ran.

Recorded consumers:1FD930 roll-target calculation;1FFE80 lateral movement;
200CE0 the script's0x800 reaction;200B80 the sibling0x1000 reaction. The
counter is therefore broader than a reaction-only setting. Exposed increment
and decrement calls should be balanced only within the original object's
lifetime and native script scheduling contract.

5. Ship extent queries have reproducible tie behavior
------------------------------------------------------
3:104/105 call1FFBA0â†’1FB350â†’206170â†’52E520. Player component selector+1304
chooses one of AEF488/AEF4B0/AEF4D8. Record+8 is compact ship data. Its WORD+2
contains three4-bit extents; signed bytes+4/+5/+6 are axis offsets. The XYZ
result is (nibble - abs(signed offset))*10, W0. The calculation can produce
negative values; it does not validate the backing resource or geometry.

3:104: X if strictly below both others; else Y if strictly below both; else Z.
3:105: X if strictly above both others; else Y if strictly above both; else Z.
Consequently (10,10,20) gives20 for3:104, and (20,20,10) gives10 for3:105.
Calling them ordinary min/max would be false. A small native comparison-region
interpreter checks the exact branch behavior, including equal and unordered
cases. Actual compact-data outputs are finite integer multiples of10.

8. Uses and remaining boundaries
--------------------------------
These metadata can support a script browser that identifies player queries,
distinguishes cached pulses from persistent state, explains attenuation,
shows reaction/vibration dependencies, and warns about extent tie behavior.
They also give concrete building blocks for a Gummi training sequence or
scripted directional reaction, provided a later implementation supplies the
original context, valid objects, resources and correct scheduling. This
study does not implement or endorse an unchecked trainer call button.

All selected semantics are bounded. Unexpanded direct calls and virtual calls
remain in the evidence. Native allocation/resource loading, arbitrary class
overrides, effect callbacks, cleanup reentrancy and imported CRT internals are
not claimed complete. Imports are resolved from the original PE declaration;
the captured cosf/sinf/sqrtf thunks are exact jump boundaries, not OS proofs.
No global mutex/barrier, external-thread safety, native bank bound or complete
bank/game reverse engineering is inferred from the body count.

The model checks use the captured selector instruction bytes, packed signed
offset arithmetic, DWORD wrap boundaries and scalar/unrolled float32 factors.
They assume ordinary IEEE rounding and masked floating exceptions, and do not
test runtime scheduling, object lifetime, resource allocation or gameplay.
