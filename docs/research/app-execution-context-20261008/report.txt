Result
The normal outer App path is closed through actual PE/CLR metadata, event registration, native thread creation and virtual dispatch. The WinForms window/message loop and the gameplay App update execute in different registered contexts. A second native worker performs timing/presentation work. This closes the former outer-dispatch gap; it does not prove exclusive ownership of all Actor/STATUS operations.

2. Actual window and worker registration

ManageRun (060000BC, IL RVA38ADC0) performs:
  Application.EnableVisualStyles();
  Application.SetCompatibleTextRenderingDefault(false);
  form = BaseSimpleForm.createInstance(app, title);
  Application.Run(form);

The API contract runs the message loop on the calling thread. createInstance reuses its static instance when nonnull; otherwise it constructs BaseSimpleForm. The constructor retains the native App pointer, initializes state, creates components and the window handle, and registers real event delegates. In particular, IL00E6/00F1 registers OnShown; IL012E/0139 registers OnFormClosing; IL0145/0150 registers timer1_Tick. 4. Pause and window behavior

Managed suspend06000223 pauses sound if suspendFlg was false, calls native127EB0, then sets suspendFlg.127EB0 only stores byte1 into device+776. Managed resume06000224 returns immediately when forceSuspending is true; otherwise125A10 clears device+776 and sound is resumed when appropriate. Neither native setter contains an acknowledgement, wait, join or Actor-lifetime lock.

OnResize ignores requests under ignoreOnResize. When resize reason2 already matches the framebuffer size it returns. Otherwise normal/maximized state invokes resume, while the remaining minimized state invokes suspend, subject to those earlier guards. OnResizeBegin is an immediate return. OnResizeEnd conditionally requests native resize. OnDeactivate changes cursor/panel visibility; its captured body does not directly suspend the device.

The timing loop1287D0 watches stop+808. Pause+776 can first cause a GPU fence Signal/SetEventOnCompletion/WaitForSingleObject(INFINITE), then a Sleep10 loop until stop or resume. It still runs SteamPlatformTick after its pause counter exceeds60. Before the pause section, ordinary timing work may signal semaphore+768 and call optional device+728 at128C4D. Thus there is no demonstrated universal stop of native callbacks, Actor activity or all other workers. The GPU wait can also delay reaching the stop check.

Managed WndProc0600020C handles sizing aspect correction, input device-change messages, overlay cursor visibility and WM_APP+1. The latter synchronously executes managed AnyMessage and writes a boolean result through LPARAM.1042E0 is the native caller that pauses sound/device, SendMessageA(0x8001), waits while its result remains-1, then resumes; selected message IDs can request App exit. 5. Normal exit path and remaining failure boundaries

After121D90 returns,127ED0 calls579BC0 before_endthreadex(0). The exact exit fixup is747C30 ->060000AA (with companion747C28). It is not the neighboring texture-animation dialog token060000CF.060000AA calls BaseSimpleForm.ExitApplication0600020A:
  if theInstance==null or theInstance.myFormClosed: return;
  if InvokeRequired: Control.Invoke(exitApplication delegate);
  else: exitApplication();
The delegate sets appClosed=true and starts a WinForms Timer. The Timer Tick stops itself then calls Form.Close(). Control.Invoke is synchronous by its API contract; the delegate itself schedules the later close rather than waiting for the worker.

OnFormClosing checks user-close reason3 when appClosed is false. Native IsReBoot38C970 is exactly signed App+4760>=0; a true result cancels. Otherwise it force-suspends around a confirmation dialog and cancels if result2, then clears forceSuspending and resumes. If cancellation is false it stores myFormClosed=true BEFORE DXInput.exit and GX.exit11AD80.

11AD80 then:
  set device+760 to-1 if it was nonnegative;
  set global App+4752 to256;
  if App handle+784 exists, poll GetExitCodeThread while result259, Sleep100;
  CloseHandle(+784), clear+784;
  set timing stop+808 to1;
  similarly poll/close/clear timing handle+792;
  free semaphore wrapper+768 (the field is not cleared in this body).

The successful valid-handle path waits for these two workers. Both GetExitCodeThread return values are ignored; neither polling loop has a timeout. The initial output values are not established by this body when the API fails. CloseHandle success is also not tested. The code is therefore not evidence of fail-safe global shutdown after invalid/stale handles or API failure.

Marking myFormClosed before waiting lets a later worker exit helper skip its UI call. This is a normal ordering observation, not an atomic handshake. A worker that already passed the boolean check and then blocks in synchronous Invoke while the UI is in the worker polling path forms a potential blocking cycle. This is a conditional static scheduling concern; the study does not prove that the race occurs in a reachable retail run, its frequency, or a sufficient live fix. Do not use this concern as a claim that normal exit always deadlocks.

If the input HWND is null,11D0A0 registers native WndProc10EB40 and tries to create AxaSimpleWindow. Registration/window-creation failure continues with null HWND. This is a fallback branch, not the shown managed Form path. Its WM_DESTROY repeats the two-worker polling/free sequence and posts WM_QUIT. Initialization closes preexisting thread handles before replacement without an earlier join; repeated-init reachability is unproved. New _beginthreadex returns are not explicitly checked before subsequent setup/priority/resume, and OnShown merely uses the returned device byte to choose panel resizing.

6. Trainer consequences

The actual App-worker entry/dispatch chain is useful provenance for a future command gate. It does not license commands from arbitrary WinForms events or injected workers. Such a gate still needs live module/object/vtable validation, actual Actor binding and lifetime serialization, and closure of relevant worker callbacks. Pause/minimize, an exit flag, an idle active stack and a closed handle are insufficient quiescence signals. Earlier suspended-fiber evidence remains relevant.

No production code, installer, IPC, UI control, process action, live test, injection or save changed in this study. In particular, this package does not solve or ship a new Drive Form feature.
