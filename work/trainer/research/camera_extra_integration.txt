CameraExtra integration for Root (slots240..248)

Include CameraExtraFeatures.inl after WorldFeatures.inl. Call CameraExtraCapabilities,
CameraExtraSnapshot, CameraExtraTick and CameraExtraReset alongside other modules;
route CameraExtraHandle(c, slot, args, result) for slots240..248. Normal disconnect,
heartbeat/fatal reset must invoke CameraExtraReset on the engine thread.

Root-owned World functions required:
  bool WorldCameraExtraIsHeld();
  bool WorldCameraExtraSetRoll(float radians);
  float WorldCameraExtraRoll();

WorldCameraExtraIsHeld must require the current valid camera lease, freeCamera,
owner0 and fresh callback-write permission. SetRoll rejects nonfinite/outside
[-pi,pi] and delegates to the same held lease; only trainer-owned heldRoll changes.
Roll() is read only after IsHeld; it returns the held angle in radians.

World CaptureCamera captures Camera+120 separately from Up. Validate finite and
bounded [-pi,pi] before taking ownership. At CameraFrame, apply19D340(camera,eye,
target,up), then19D3D0(camera,eye,target,heldRoll). Full ASM proves the latter ABI:
RCX camera, RDX eye, R8 target, XMM3 roll. It leaves Up unchanged. Native19CBA0
then composes this roll in the view. Do not also rotate Up by the same angle.
Drop held state when ownership/submode/scene changes. Never replay old banks.

World Capture/Frame/IsHeld should bind scheduler716868, sceneheap9BA920, full10-byte
MapTarget717008 and controller submode int32 at718CA8 (controller718C60+72).
Require owner int32AC1528==0. A pending event can acquire/release within the same
room; retaining just world/room bytes is insufficient. Normal native follow
writes FOV and roll again on each update, so no broad memory baseline restore.

CameraExtra owns a separate wrapper for existing follow task164860(group1,
priority26000, continuation0). It does not call an additional camera update.
Queued recenter/snap actions are consumed immediately before the normal task and
are bound to a fresh player/status/controller plus scene identity. All original
callbacks are called once even when the action is canceled. Reset restores only
an owned callback found in a freshly validated list; no task address is cached.
