1. NATIVE ACTOR / EFFECT FREEZE — REAL CONSUMERS, PARTIAL PAUSE

Flag: uint32 at RVA 2A11400, mask 0x20.
Set: void __fastcall sub_1403ABDB0(), OR 0x20.
Clear: void __fastcall sub_1403ABDA0(), AND ~0x20.

This flag has substantial native behavior beyond particles:
- 3BFD30 branches on sub_3BAAD0(actor) OR global bit 0x20. In the frozen branch
  it skips the normal Actor vtable update methods at +16/+24/+32/+40, motion
  advancement 3C6740, movement resolution 3B89A0 and several post-update paths.
  Pose/model maintenance 3C73C0 remains active. Actors remain in the subsequent
  native pose/render submission list.
- 16E610 skips object virtual update methods while retaining list submission.
- 1E7880 skips motion/update/color timers while retaining its render list.
- 2BD190 tells the effect subsystem to suspend playback and skips effect timing.
  Effect type 3 is explicitly exempt from this global freeze.
- 2BD730 suppresses normal effect cleanup for frozen types.
- 3C55F0 skips a list of VM-backed effects and cleanup.
- 3D9130 returns before part of its controller update when argument a2 is false.
- 3F4860 leaves eight VM-backed task slots alone after its initial helper call.
- 4376B0 stops one attack-shape interpolation timer but continues shape handling.

Native debug evidence is unusually clear: unreferenced code at 4207C0 and
4207E0 reads the debug pause-mode byte at RVA 749811. Mode 1 calls exactly
3ABDB0 / 3ABDA0. Mode 0 instead toggles bit 1 at RVA 2AF2C30. Getter 420D10
selects the same source. The other debug-mode bit has no discovered live
scheduler consumer and must not be presented as a working pause.

There is also a reachable event opcode, 2DA910: if its condition passes,
its byte argument selects the same freeze setter or clearer.

LIMITS THAT MUST APPEAR IN PRODUCT DESCRIPTION
This is an actor/effect freeze, not full simulation pause. 3BFD30 still runs
the Actor vtable +8 pre-update and some flag/render bookkeeping. Mission tasks,
fiber waits, collision/attack task 3CFF40, and outer timers do not universally
test this flag. Attack shape intersection and damage processing can therefore
continue in some states. Existing type-3 effects can advance. Audio can continue.
It is inappropriate to market this as a lossless deterministic frame step.

Implemented catalog: slot 79, "Freeze actors and effects", toggle.
Proposed guards: stable playable scene, no menu/event/transition, existing bit
must be clear when acquiring ownership. Set once, do not fight native clears.
Stop ownership when native code changes the bit or a scene transition occurs.
Compare-restore only the bit under a still-valid same-scene ownership check.
Native world reset 3ABAB0 writes the entire global flags word to zero.
Identical writes by another owner cannot be distinguished by a compare alone.

An optional "Advance frozen actors one update" could clear bit 0x20 after one
outer update and reassert it after the next outer update, using a strict state
machine. The rest of the simulation would still have been running throughout.
Do not expose it under the plain name "Frame step".

2. MOVEMENT COLLISION BYPASS — NATIVE CALLABLE PATH

Enable: void __fastcall sub_1403CBFC0(void* actor, void* optionalView).
  RCX actor, RDX optional pointer.
  actor + 0x124 / decimal 292: OR 0x40.
  actor + 0x8C8 / decimal 2248: OR 0x1000.
  actor + 0x908 / decimal 2312: store optionalView.
Disable: void __fastcall sub_1403CC3B0(void* actor).
  Clears the two bits and sets the pointer to null.

The null optional argument is proven: VM trap 53E840 decodes the actor and
calls 3CBFC0(actor, 0). Trap 53E870 calls the clear function. In the extracted
VM table these are bank 6, indexes 35 and 36, one argument, no return value.

Consumer proof:
3B89A0 checks actor+292 bit 0x40. When set it computes movement from existing
controller/root-motion vectors, adds it directly to position at actor+1648,
updates displacement bookkeeping and omits 3B9090.
Normal branch calls 3B9090, which performs Actor separation, world collision,
ground resolution, landing/leave-ground events and related floor data updates.
Thus the bit bypasses movement collision. It does not provide flight controls,
zero gravity, immunity to attack damage, or safety outside loaded room geometry.

The companion render bit is meaningful: Actor+1968 is the render object, so
Actor+2248 is renderObject+280. 189470 handles bit 0x1000 by bypassing its normal
spatial partition checks, allowing this special actor to remain submitted.
Cutscene routines 1C9620 / 1C9D60 use a non-null optional pointer. The trainer
must not overwrite a pre-existing special-mode pointer or an active native mode.

Proposed catalog: "Bypass movement collision"; slot allocation pending root.
Requires a freshly validated player actor, native stage stable, no menus/event,
and no pre-existing bit 0x40, bit 0x1000 or non-null optional pointer.
Capture ownership of the actor generation, world/room/entrance and scheduler.
On disable restore only when the same live actor/generation is still current
and the three fields still match the trainer-owned mode. Never dereference an
old actor after a scene change. Stop on transformation/actor replacement.
Do not force this mode every frame if native code changes it.

3. FULL PAUSE WITH ACTIVE RENDERING — INITIAL ARCHITECTURAL FINDINGS

Update2026-10-04: slots116/117 now implement complete FIELD scheduler pause
with the outer native captured-image draw task preserved. See field_pause.txt

The field module is at RVA 716860, its scheduler [716868], state 716884.
Native module fiber 150310 dispatches the complete inner scheduler only when
state == 1. State 2 skips both simulation and render tasks.
The field fiber is in the outer scheduler at priority 130000. Native menu
module uses priority 140000. Native pause capture task 1515E0 is priority 330000.
1505A0 creates module fibers using14F8A0, so replacing their callback after
startup would not intercept resumed execution: scheduler14FD60 checks the
continuation pointer at task+112 and resumes the fiber directly.

Native normal pause also sets timer mask1 via157130, enables captured-frame
drawing156780, captures153430 and then sets module state2. Resume1514B0 performs
more work than state1: clears captured-frame mode under context conditions,
updates menus/input and other subsystems, then restores the module state.
The capture texture is [9BAA08];1533B0(216) blits it through the PC renderer.
That path could preserve a static world image while trainer UI is live, but
does not permit moving free camera around the paused world. Proper placement
in the renderer lifecycle and texture ownership still needs runtime validation.

Group filtering is not a complete solution by itself:
- Normal field render tasks registered162F20 use group3; dual camera162C50 uses5.
- Actor simulation task3BF550 is group1/priority20000. It executes a separate
  actor scheduler and ultimately also prepares actor render submission.
- That actor scheduler has controller fibers, BDX work and pose maintenance.
  Suppressing it entirely may leave no rebuilt actor render list.
- Some group3 render tasks advance effects unless the native freeze bit is set.
- Dispatcher14FD60(mask,equals) filters groups, but module150310 calls the
  unfiltered wrapper14FC20. No verified virtual dispatch slot replaces that
  call. An interception at this point would require another code hook and a
  carefully specified simulation/render separation, not another guessed flag.

Actor/effect freeze and collision bypass retain their exact behavioral names.
Full pause with MOVING free camera or deterministic fixed-time stepping still
requires simulation/render separation. The captured-image implementation is
described separately and does not claim those behaviors.
