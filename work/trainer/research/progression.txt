STATUS AND ABILITY REFRESH
3C2100(status) first runs3C2120 to copy liveHP/MP/Drive/timers into save, then3C1D90 rebuilds level/equipment/ability values. Consequently it is suitable after ability/equipment edits, but would overwrite prior direct saveHP/MP edits.
Status is632bytes: packed characterSave+592, packedForm+596, charID+608, packedActor+616, packedDriveSave+620. Actor's native Status pointer is+1472. Packed pointers use game's decoder. Current actor backlink and character record are checked.
3C03F0 initializes DriveSave+620 only for Sora/Roxas. Non-Sora companions normally have zero; rebuild skips their DriveSave block. CanRefresh accepts null for these characters and only the exactSaveCharacters pointer when nonnull.
Rebuild uses lvup pointer2AE58A8; equipment-stat pointer2AEA8A0 with sorted16byte entries; ability parameter pointer2AE5760 through offset372 (376bytes needed). Every nonzero equipment-effect ability and character ability must exist and have native effect ordinal ushort(item+4)<256. The effect bitset is32bytes.
Form data has its own weapon and24abilities. Progression's character-ability/equipment edits and sharedEXP addition currently require normal form for affected active actors. Player module separately validates its form-specific path.
Journal collector368ED0 stops at first empty character ability ID. Remove now shifts later entries left, preserves their enable bits and zeroes the last entry. Removing just a WORD would hide later abilities from these consumers.

EXP AND LEVEL LOWERING: COMPLETED INVESTIGATION
3ECF30 adds to sharedEXP (Save+14048), caps only the upper bound9999999, and loops13character records. It advances each level up to99, processes3ED7D0 rewards and refreshes active statuses. Negative input/overflow are not handled safely by the native function, so wrapper only sends a positive bounded delta.
lvup has16byte rows: EXPi32+0,STR/MAG/DEF/APbytes+4..7, choice rewardWORDs+8/+10/+12. Character+14 chooses the reward column. Current native difficultyDWORD3 modifies Sora/Roxas AP to3/2 of tableAP (3EDA00).
3ED190 is another upward-only advancement routine; xrefs were only metadata/unwind in this build. Searches of character getter callers, level-byte writes, both native level routines, status initialization, debug dialogs and full decompile index found no inverse reward routine.
Abilities contain only ID and enabled bit. They carry no provenance saying whether acquired by level, bonus event, form growth, preset or trainer. 3EDF90 bonus rewards separately affectHP/MP/Drive/slots/items. Deleting an ability solely because its ID appears in a level table can delete an ability acquired another way; duplicate abilities are meaningful for additive effects.
Therefore an exact retrospective level-down is not reconstructible from the current bytes alone. A future explicit 'change level and retain rewards' operation could lower level/EXP and rebuild baseline stats, but it must say rewards remain and sharedEXP affects other characters. A genuine restoration should use a known earlier backup. No misleading automatic inverse-level command was added.

EQUIPMENT: COMPLETED INVESTIGATION
Armor/accessory arrays are char+20/+36,8WORDs each; unlocked counts+16/+17. 3C1D90 loops these and applies3C1190 stat/equipment-ability data. Neither type loads a visible weapon model. Implemented actions validate correct type14/15, real bag ownership, unlocked slot and room for returned old copy; transfer bag counts and equippedWORD as one checked game-thread edit, then rebuild active normal status. They do not manufacture copies.
Primary/secondary weapon WORDs are char+0/+2. 3A1780 writes these only; no stock bookkeeping, model update or invalid-ID protection (invalidcharacter can write0/2). Story-special3A1600 temporarily swaps primaryweapon while retaining priorWORD at9AD89A. Thus neither routine is a universal equip API.

UNLOCKS / WORLD PROGRESSION
Unique summon/map/report records can be acquired by the normal native grant handler. Forms are excluded because3C3FE0/3C4220 also resolve command data, initialize a form weapon by removing a stock keyblade, and clear antiformEXP. Setting only the ownership bit would skip initialization.
World flags atSave+16440 have256bits. 3DF2E0 changes a flag, looks up the current worldflag table and queues a script event;3DEEF0 consumes it. A missing flag definition can be dereferenced. 3DF060 resets and applies initial scripts. Blind allflags writes/reset are not suitable universal unlocks.
Storyflag accessor39A980 packs world in upper bits and flag in low10bits, but actual world block stride is32bytes=256bits. Bounds must be world<19,flag<256; blindly accepting all low10bit values aliases adjacent worlds. Nativeinit19world blocks differs from local OpenKH schema20; native evidence takes precedence.

BACKUPS
Raw memory backup should capture69568bytes coherently on game thread and include buildSHA/header/version/timestamp/scene metadata. Preserve all unknown bytes.
RawKH2J buffer is not the Steam save-container file. Back up actual disk save files separately; restore disk files with game closed, then load normally.
2ED0E0 is only memcpy and does not rebuild actors, scripts or current world. Full live restore by that call alone is incomplete. 2ED110 is a finalized save export: it adjusts snapshot-specific bytes, obtains RNG and computes checksum, so it is not a pure raw snapshot helper.

OTHER RELEVANT FINDINGS
Workshop materials differ from bag stock. 2AAD70 delivers60materials, increments per-material and cumulative counts atSave+18996/+19252 up to999 and sets acquisition bits at+18932. 2AAF20 consumes recipes into workshop flags at+18948. Bag quantities alone do not equal workshop progress.
