SORA ANIMATION TOOLS — v0.5

Implemented: actor-bound desired speed0.1..3, enable/disable and nine runtime
readouts/status values at slots160..170. The supported character is Sora including
Drive Forms. No claim is made for Roxas or other player classes.

The native speed is actor-wide and survives ordinary motion changes. Commands
write it once; Tick monitors ownership instead of continuously forcing the value.
Changing rate affects animation-derived movement and attack/effect timing.
No frame seek, motion ID write, resource-header mutation or fake animation freeze
is implemented. Zero is deliberately excluded as a selectable rate.

SCOPE AND RESTORATION
A lease binds the current Actor/status/controller owner/form, scene heap, field
and Actor scheduler, full10-byte room identity, model object/resource/vtable.
Only a fresh supported Prototype/RAW resource produces frame/duration/ID readouts.
Normal motion changes retain the rate. Model/resource loss ends the lease and
can restore speed only on the still-proven same live Actor in a stable scene.
Actor/Form/scene loss never follows an old Actor pointer. An unsafe or unready
scene, lost native-writer observation, or uncertain ownership prevents restore;
the existing field is left to the engine. Thus Off does not promise actual rate1.
The separate current-rate readout shows the actual current field when valid.

SCRIPT WRITER
VM bank1/index107 is a16-byte record with callback42FCE0 and two8-byte operands.
The callback pointer alone is compare-exchanged; metadata stays unchanged.
The pinned bridge observes script ownership, including writes of identical float
bits, then forwards the exact original once. It never retains stack arguments.
A private SRW lock covers observation+Original and all trainer speed mutations.
Script signals are checked directly by Reset, not only by Tick. The original
exception propagates; __finally releases the lock. The observed native callback
only decodes pointers and stores a float, with no recursive callback path.
Unhook restores only the trainer-owned slot. If protection restoration fails,
the resident forwarding wrapper remains safe and a later tick retries removal.

DRIVE INTERACTION
Fresh complete ASM covers the entire native constructor chain and seven transfer
helpers called by40D000. The new Actor's constructor sets speed1. No transfer of
old Actor+680 or bulk controller copy was found. Subsequent native scripts may
choose another rate. MotionTick follows DriveTick and a freshly read context;
the trainer never renews its old lease onto the newly created Actor.

VALIDATION AND LIMITS
454 synthetic checks passed, no compiler warnings. Tests cover both formats,
actor-wide lifetime across motion changes, exact baseline restoration, same-value
and changed-value script writes, callback ABI/original-once, a concurrent writer
versus reset, native exception propagation, bank/slot ownership, CAS/protection
failures, teardown, heartbeat/wrap, model/form/room identities and invalid headers.
No game or UI action was performed. Synthetic callbacks do not prove actual
rendering or all timing interactions. Future/malformed model assets and arbitrary
mods are outside the evidence. A direct external same-bit field write that bypasses
the observed VM callback is indistinguishable; complete address/identity reuse
between samples is likewise not disproved.

MotionFeatures.inl WriterHook / Stop / Start / UpdateRate
Private SRW lock serializes observation+native original with all trainer speed mutations. Equal-value script writes revoke ownership before the original. Reset verifies script signal, slot/bank validity and fresh Actor ownership under lock before comparing/restoring bits.

Limitations: Arbitrary third-party direct writes that bypass this callback and write identical bits are not detectable. The private lock coordinates this wrapper and trainer writes, not all external modules.

MotionFeatures.inl CurrentOwner / Maintain
Lease binds current Actor, status, controller owner, form, scene heap, field/Actor schedulers, all10 room bytes, model/resource/vtable. Normal motion changes survive. Actor/Form/scene loss never dereferences an old Actor for restoration. Model/motion loss can restore the Actor-owned field only when the exact current Actor/scene remain valid.
Evidence: ../../../trainer/Native/MotionFeatures.inl, ../tests/MotionGuardTests.cpp
Limitations: When identity, scene safety or writer observation is uncertain, no restore is attempted; the current field is left to the engine. Exact ABA reuse of all identities between sampled updates is not ruled out.
