Public API

  void MissionSnapshot(const TrainerContext&)

  MissionTick and MissionReset exist as no-ops for interface consistency.
Root calls Handle/Snapshot/Capabilities after native Update on g_gameThread.
There is no persistent override, queue, event hook or retained Actor/Mission pointer.

Native call ABI and effects
  char __fastcall restart(int seconds ECX, int timerIndex EDX)
  RVA3FB9A0, timerIndex always0; return AL is not a success value.
  Active Timer flag4 avoids the optional virtual+16 HUD-create branch.
  Then3FA5D0:
    seconds>0 ->157140(seconds): mode1, duration/display=seconds*60
    seconds<=0 ->157170(Timer+36): mode0, duration=configuration*60, display0
    157190: origin=current clock ticks, phase1
    157110(2): clears native timer/script pause ownerbit2
Module checks exact complete bytes of all eight synchronously reached functions:
3FB9A0,3A39F0,3A3970,3FA5D0,157140,157170,157190,157110.
The optional activation branch is excluded by an already-active timer gate.

226: args[0] whole seconds1..3599. May switch a count-up to countdown.
The bound keeps ordinary numeric HUD below onehour; it is trainer policy,
not a claim that multiplication requires such a small upper bound.
227: no argument; sends0. May switch a countdown to count-up.
Existing Timer+36 limit must be nonnegative and <=35791394, preventing signed
32-bit overflow of limit*60. Zero has no configured deadline. The limit field
itself is not modified. Native count-up display caps215999frames=3599.9833s.
Because cap check precedes deadline check, a configured count-up limit above
the cap does not generate timer-timeout on this native path.

Mutation gates
- Nonzero gameThread matches current thread; bridge enabled; shared host exists;
  nonzero heartbeat age<=5000ms using wrappingDWORD subtraction.
- Fresh context with correct base and playable scene. Native ready1, module
  closing0, no pending room transition, fieldstate1 for mutation.
- No menu, event, title, captured-frame pause, current presentation2A11478,
  Game-over2AE8050, pending Drive context or Drive transitionbit2.
- Current Actor/status pair matches current player global and backlinks;
  active living characterID1..15 with sane HP. Does not arbitrarily restrict
  timing tools to Sora when another supported living player is current.
- Current mission exactly native static storage2A0F8B0, full1708-byte range.
  Descriptor+8 matches global2A0FF70, BAR+96 present/readable; heap and both
  outer/field schedulers readable.
- Mission phase1, activeflag1, neither endedflag4 nor finish-control0x10.
- Registry count0..9, entries only known inline widgets, no duplicates.
  Timer+296 is registered, ID0, exact vtable5C4208, initializedflag1,
  activeflag4, suppress-activationflag0x10 absent.
- Clock mode0/1, phase1/2 (armed/running), nonnegative display/limit and no
  pause-owner bits at all. Clock writable fields ABB854..ABB868 validated.
  Stopped clocks are rejected because timeout or ending effects may be underway.
- After native-code validation, a second fresh View must match descriptor,
  BAR, mission ID/flags/phase, registry, scene heap/schedulers and all10 MapTarget
  bytes. Timer configuration/flags and clock origin/phase/mode/limit match too.

Only after all gates does one typed native call occur. No native callbacks are
called for validation. It is not deferred to a later scene. Its return AL is
ignored; immediate postconditions check same Mission identity, phase1, direction,
duration and display. An unconfirmed postcondition yields resultcode2 after the
single call, without rollback or automatic retry. Unsafe preconditions reject
with no dispatch and no clock write.

Readouts
Snapshots use thread/host/scene/Mission resource and registry validation.
Mission phase0..4 may be displayed, including transitions. Counter/gauge objects
require registry membership, matching index and class; unconfigured inline
constructor objects are not published. Each value/max pair is validated
independently. Float gauges require finite value in0..maximum; no percent divide.
Score is separate+1088, class5C9E38, active flags and configured max9999.
The clock requires an active registered timer0 and sane native phase/mode; a
stopped or paused current clock can still be observed. Fractional seconds
are native frames/60, rather than the game helper's rounded-up seconds.
Unavailable objects have no valid-value bit, not a fabricated0.

Ownership, restore and limitations
Restart is a one-time native action. Disable All and disconnect do not undo it.
Normal mission events, progression and rewards continue. No auto-save is called.
Numeric HUD reads direction dynamically (18D830 ->1570D0), supporting both
directions. Native active-timer restart does not reset final-seconds warning
latchesHUD+7824; previously played warning effects/sounds may not repeat.
The module does not claim a complete generation token: repeated same-resource
static-storage ABA and arbitrary unsupported concurrent game-state modifications
are outside its proof. It relies on the native engine-thread sequencing used by
the original script callback. Full-BAR validation is unnecessary for this narrow
already-active call path because it does not parse/dereference BAR/HUD resources.
Counter/gauge writes remain open research: setters synchronously invoke mission
scripts, Actor broadcasts, persistent progress and possible map transitions.

Validation
1092 isolated checks,0failures, MSVC/W4 no warnings via build_mission_tests.cmd.
NativeRestart is the sole replaced game callout; fake memory carries the real
offsets. Tests verify exact arguments, both directions, configuration limits,
signed multiplication boundary, 32-bit tickwrap, current Actor gates, Mission
reconstruction and preflight state changes, expired hosts, code mutations,
paused/stopped states, readout availability and no retries/rollback.
No game process was accessed; no UI/live test was performed.
