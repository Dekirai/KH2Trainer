Independent forced-Drive review
================================
Scope: exact forms 1..6, including Anti; ignore normal Drive cost, party eligibility,
unlock inventory and random Anti/Final selection. From any existing form 1..6,
perform native Revert before a fresh Base Sora starts the requested form.
Read-only analysis; no game execution or source edits by this reviewer.

--------

Entrypoint and lifetime contract
------------------------------
Call 0x14040CE60 on the validated game thread as void(actor RCX, form EDX).
Ignore its incidental AL/RAX value; verify the queued native context separately.
This skips 405440's RNG, cost, usage-counter and command-validator policy.
40CAA0 copies actor/form into a native allocated context and queues native callbacks.
No trainer stack record or DLL callback is retained. 40D000 performs resource
loading, pose transfer, actor replacement and form-status initialization.

For a transformed source, queue form0 first. Continue only after native pending
context2AE9FA8 is gone, transition bit2A10504:2 is cleared, a different validated
Base Actor is current, and the saved-partner count2AE9790 is0. 40D000 creates the
Base Actor before Revert's continuation and 40CF20 cleanup finish. Using only its
form byte would race partner restoration and native pending-context ownership.

400990 appends partner selectors without checking the two-element capacity.
Any direct Base-to-nonzero-form call therefore requires saved-partner count0.
400B20 tolerates missing/dead partners; its selection does not impose a minimum
party. 400440 restores matching saved world-party selectors and resets count0.
This capacity requirement does not reintroduce the ordinary party eligibility rule.

Track the trainer's queued context identity/source/form while it remains live.
If another native transition replaces it, cancel pending trainer follow-up only.
Do not free or abort native work. Scene/heap/scheduler changes, heartbeat expiry,
disable, timeout and explicit cancel must similarly drop only pending trainer steps.
After Revert, revalidate all data against the fresh Base Actor before requesting
the second stage. Never retain and reuse the former actor or status pointer.

Zero gauge and locked forms
--------------------------
3C17C0 initializes a separate positive formtimer from (level+3)*paramsFloat104.
Anti uses (paramsInt140+1)*paramsFloat104. It does not read Drivebars433.
3A92C0 drains timer436 using frame time, params108 and the status effect factor;
3C0B50 clamps it to0..max440. 405320/404A40 start expiry Revert only when timer<=0,
subject to native action/command gates. Thus no artificial Drive refill is needed.

3A0E70 initializes all ten form records even when locked: level1, weapon0,
zero EXP/abilities. 3A7A40 stores the selected form and looks up status using
3C0620(character,form), with no inventory/unlock test. 3E0CC0 returns0 for weapon0;
the constructor skips that optional weapon model. This supports forcing locked
forms without changing unlock flags. The untouched form may lack an optional
offhand; this review does not silently grant equipment.

Anti-specific resources
-----------------------
405030 always accesses command/UI row29. For Anti it copies the64-byte row into
an override slot and assigns message50255; other forms clear that override.
3AD440/500/540 prove exactly six slots at2A114A0, so row.byte36 must be<6.
3AD480 can rewrite matching row fields under configuration flag25; require the
row writable as well as the384-byte override array writable.

3AD9A0 searches masked ID0x444F through message tables2A11668/78/88 in order;
on failure it searches fallback0xADC in table2A11678. Table rows are sorted16-bit
IDs, stride8, and contain table-relative offsets. Bound the count and offsets;
validate the first native-selected result or the required fallback. Readable
zero-terminated byte checks are a limited preflight, not a full validator for
arbitrary modified message command streams.

Other required safety gates
---------------------------
Retain scene/event/modal/pause/summon/transition exclusions, live Sora identity,
controller and status-backlink consistency, full bounded actor-list membership,
valid status pool/refcount, readable native heap/schedulers, valid world costume
and requested object rows, save/header/status-rebuild/equipment/ability data,
finite positive timer parameters, and exact native entrypoint bytes.
Use the current implementation's guards rather than calls from a worker thread.
The engine assumes allocation success in portions of40CE60 and40D000; read-only
pointer gates cannot prove future heap allocation success.

Concrete synthetic and later runtime cases
-----------------------------------------
1. Base Sora, zero bars, no party, locked target: forms1..6 queue selected form
   directly, preserve unlock inventory and bars, and avoid RNG/dispatcher calls.
2. Each active form1..6 to each target: only Revert queues first; no second call
   while pending context, transition lock or saved partners remain; the second
   call uses the new Base Actor, never the original pointer.
3. Saved partner count1/2 on Base rejects nonzero targets before native call;
   count0 permits missing party. Count outside0..2 always rejects.
4. Missing row29, slot6, unsorted/duplicate rows, unreadable override, missing
   Anti message plus fallback, invalid relative message offset all reject.
5. Anti available in any of the three message tables follows first-match order;
   valid fallback works when target text is absent.
6. Invalid status pool/backlink/form record, missing requested/base model,
   malformed abilities/equipment or nonfinite timer factors reject before call.
7. Native queue identity replaced, world/heap/scheduler changed, host heartbeat0
   or older than5000ms, timeout/disable/cancel: no trainer follow-up or native free.
8. Queue accepted but actor never replaced does not report completion; incidental
   native return values do not decide success. Expired timer does not certify a
   completed requested form.
