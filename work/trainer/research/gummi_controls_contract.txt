Integration
-----------
Include after GummiFeatures.inl in the same bridge namespace.
bool GummiExtraHandle(const TrainerContext&, unsigned slot,
                      const double args[8], TrainerResult&)
void GummiExtraSnapshot(const TrainerContext&)
void GummiExtraCapabilities()

There is no Tick or Reset function: these commands act once and retain no ship
pointer, callback or ownership lease. Host field-scene readiness may be false;
Gummi has its own module, heap, scheduler and ship lifecycle.

Slots and ABI
-------------
320 / command1320: set raw mobility bonus, signed integer -100..200.
  Native RVA225DE0: RCX=PLAYER_STATE, EDX=target-current (checked signed delta).
  Field state+36. Factor=clamp(1+scaledBonus/100,0.1,3).
  For negative values only, scaledBonus=bonus*systemparam ID0 float+16.
  Affects lateral maximum speed, acceleration and bank-angle smoothing.

321 / command1321: set raw roll impulse bonus, signed integer -100..200.
  Native RVA225CD0: RCX=PLAYER_STATE, EDX=checked delta.
  Field state+40. Factor=clamp(1+bonus/100,0,3).
  Roll impulse changes; timer and invulnerability ownership remain native.

322 / command1322: set raw lock-on bonus, signed integer0..1000.
  Native RVA225DB0: RCX=PLAYER_STATE, EDX=checked delta.
  Field state+44. Future enabled-category reloads use
  max(parameter+16, parameter+8 - bonus*parameter+12).
  Current timers, sight objects and target selection are not reconstructed.

323 / command1323: add native special-weapon charge, integer1..900 base points.
  Native RVA230BD0: RCX=inline COMBO at player+4872, EDX=points.
  The native multiplier is1+PLAYER_STATE+52/100. Gain truncates to int and is
  added to combo+56; each100 points increments stock+60 up to9. The full state
  has progress100 and flag4, which native activation later consumes/clears.
  Does not install missing weapons, force attacks or reset combo phases.
  Action has one argument field and no ValueSlot.

324..326: stock0..9, progress0..100 and phase0..5 of the validated installed combo.
327: finite player+1512 roll countdown, displayed at least0, in engine ticks.
328: effective movement factor0.1..3.
329: effective roll impulse factor0..3.
320..322 also publish their actual current signed integer values.

All bounds on edited raw bonuses/points are trainer policy. Readouts can expose
finite native values outside the edit policy. No RAX return value is interpreted
as native success; the void call is dispatched exactly once after validation.

Gates and ownership
-------------------
Reuse gummi::BuildContext, ActionReady and SameLifetime. Native calls require the
bridge game thread, nonzero heartbeat no older than5000ms, enabled bridge, live
gb module membership and exact descriptor/state identity. The module must be
running, mission phase8, ship phase2, positive HP and no dead/rebirth flags.
The scene heap and scheduler must be current and consistent with the module.

Each command rebuilds the context immediately before dispatch and confirms the
same player/state/heap/scheduler/route/variant. Relevant field values, tuning or
lock-on row pointers, and combo contents are checked again. No old pointer is read
after native dispatch. Nine complete function byte signatures protect callouts
and the directly relevant native getter semantics.

Mobility/roll require the current playerparam ID0 row and finite native products.
Negative mobility additionally checks systemparam ID0. Lock-on requires the
embedded LOCKON class and four row pointers inside the loaded lockonparam table.
Combo charge requires its main ship/state backlinks, installation state, bounded
stock/progress/stage/phase and finite timer. Float-to-int conversion and subsequent
integer addition are bounded before dispatch. The helper never fabricates an
installation flag or attack resource.

Restoration and save behavior
-----------------------------
These are one-time runtime changes. The native loadout aggregator or a replacement
ship may overwrite them. Disable-all/disconnect does not undo them; profiles cannot
store/reapply them. No design file, inventory or save field is directly changed.
Normal combat and later mission results can still reflect altered ship behavior.
