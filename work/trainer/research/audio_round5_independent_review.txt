Independent audio listener review — 2026-10-04
Reviewer: managed_tools

No blocking issue found in the proposed read-only contract. This review covers
the contract, not a new implementation or a live audio test.

All88 supplied native ranges were compared to the original PE hashes and full
page counts. Seventeen critical functions were read completely: constructor,
destructor, create/lookup/delete/list-clear, selection/update, global update,
locks, matrix-controller lock order, base/point/line update and normal cleanup.

Confirmed constraints
---------------------
1.077FC0 acquires global Sound CS before072070 clears selected+120 and before
  entering the manager CS. The snapshot must retain that outer lock throughout.
  An inner-lock-only read would not cover selected-pointer clearing.
2.0322A0/032390 use global then manager lock order and release manager first.
  Nonblocking TryEnter in this order is appropriate for the stated snapshot.
3.071640/071740 destroy members and compact/reset the list without clearing
  selected+120. The contract's full-list membership test before dereference is
  necessary. A nonnull selected pointer alone may point to freed storage.
4.072070 uses unsigned priorities; the later enabled member wins a tie. Reading
  priority as signed would misselect values with bit31 set.
5.Listener kind is BYTE+8, ID is DWORD+12, backlink is QWORD+16. Base and point
  objects need136 readable bytes; line objects need184. Count/peak/capacity are
  signed DWORDs at manager+24/+28/+32; the pointer array is at+768.
6.The native create routine can insert null after allocation failure. Rejecting
  any null among the counted members is justified; checking only selected is not.
7.Base and point update return the enabled bit. Enabled line update returns true
  even if an endpoint ID was absent; this is not an extra false-return condition
  that invalidates the contract's selected-cache interpretation.
8.Manager destructor070E20 deletes the CS without clearing byte816. That byte
  is not an ownership generation. Normal verified application post-Update
  sequencing is essential before even trying this manager lock.
9.077BE0 joins audio workers before deleting the manager, then clears the global
  only after the destructor returns. Global nonnull and vtable checks alone do
  not provide a worker-thread lifetime lease.

Implementation clarifications
-----------------------------
- Capture the acquired CS addresses, and always release those addresses, inner
  before outer, on every successful-acquisition path including validation failure.
- Do not emulate the native wrappers by writing initialized byte816.
- A bad active selection invalidates its ID/type/priority/position together;
  structurally validated counts can remain available separately.
- The display is last native audio-update position. Finite values are not proof
  of equality to the latest listener matrix, camera position or current frame.
- No setter, creation, selection override or recomputation is justified by this
  review. Listener setters can call observers; existing proposal avoids them.

Precise limitation
------------------
This retains the existing observed native lifecycle assumption. Foreign mods
calling private audio teardown from another thread, arbitrary memory corruption
and every pointer-reuse episode are not excluded by static structure checks.
No product file, running game, UI or IDB was changed and no build was run.

Fingerprints, raw bytes for the17 reviewed bodies and all88 range checks are in
audio_round5_independent_review.json. It records the exact reviewed contract
hash so later changes require a separate delta review.
