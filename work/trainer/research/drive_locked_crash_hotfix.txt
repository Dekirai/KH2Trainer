KH2 TRAINER 0.7.1 — MISSING SECOND KEYBLADE

User report: Final Form crashes during transformation when it has not been
unlocked and its second Keyblade is missing. Forms without a second weapon work.
No crash dump or live process was inspected. The matching native defect path
is proven statically; corrected gameplay remains untested.

Native form acquisition at 3C3FE0 / 3C4220 initializes the offhand for forms
1,4,5 (Valor, Master, Final). Direct40CE60 bypasses item acquisition, leaving
locked forms' weapon record at0. 3E0CC0(objectRow,1) reads that WORD from the
form record selected by objectRow+87. A zero item skips recursive weapon model
and MSET loading in3E0660 and weapon construction in3A7A40. Later bone selectors
reach3B50F0 ->3B5450 ->3D7600 ->3B5D40. The selected weapon pointer is dereferenced
without a null check. Prior fixture tests mocked transitions and did not execute
this resource/weapon-consumer path, so their pass did not cover this defect.

Fix: read-only preflight verifies the current form weapon. If a required second
Keyblade is missing or invalid, plan Sora's current main Keyblade after validating
the target model, Keyblade item type, WORD(item+4) weapon ordinal, native went
mapping and the offhand wmst motion name. A valid existing form weapon is kept.
On a form switch, Revert runs first; the final plan is rebuilt from the fresh
base actor's equipment. Immediately before NativeBegin, only the target form's
2-byte weapon field changes. No unlock flags, bag counts or direct save files
are changed. With no queued native context the assignment is rolled back.

The filled slot remains after Revert/disconnect because active and later native
resource consumers require consistent equipment. A subsequent normal game save
can persist the assignment. This is disclosed in feature metadata and the guide.
The feature is marked ChangesProgression and cannot replay from profiles.

Engine allocations and the contents of asynchronously loaded assets remain
engine assumptions. Mapping and motion table lengths are recovered from their
owning system BAR entries and checked against the loaded allocation. Every used
cell must fit its entry, not merely a readable memory page. If no valid weapon/
model/motion mapping is available, reject before the native loader.

Evidence: drive_locked_crash_native_evidence.json,
drive_locked_crash_review_evidence.json, drive_locked_crash_root_batch0..3.json.
