Native Missions - deep analysis and trainer implementation
=========================================================
Status: frozen research/module; read-only IDA, no game/UI access.
Source: trainer/Native/MissionFeatures.inl
Catalog: work/trainer/research/missions_features.json
Detailed ABI/gates/slots: work/trainer/research/missions_contract.txt

New practical result
- Restart an already-active mission timer natively as countdown or count-up.
  Both directions may be switched. It is a one-time action, not a clock freeze.
- Show real Mission ID/phase, native clock value/direction/state/limit/pause,
  each of three counters and gauges with maximum, and the active score.
- Timer events and mission scripts continue normally; edits to counters,
  gauges or universal win/fail shortcuts are not claimed safe yet.

Most useful structural findings
1. Mission uses reused static storage2A0F8B0 with globalpointer2A0FF68.
   A fresh pointer alone does not distinguish two mission lifetimes.
2. The descriptor attaches from BAR type2. Constructor flag1 also exists on
   unused widgets; registry+976/count+1048 and object IDs prove configuration.
3. Counter setter3FA230 sends14/123 atzero/max; gauge3FA310 sends136/137.
   These events run BDX, Actor callbacks and condition handlers synchronously.
   Handler3F61A0 can change persistent flags and invoke progression helpers before a map change.
4. Global clock runs in native60-tick units. Timer expiry sends74,arg0; event74
   is not intrinsically failure. A mission's external script decides its outcome.
5. Score has repeat-reward reduction: a128-entry typedID history counts uses,
   and native score awards shrink by2^-repetition with floor-to1. Completion
   can convert score intoEXP. Therefore score is more than a HUD number.
6. Existing native restart3FB9A0 sends positive seconds forcountdown and0 for
   count-up with configuredlimit. An active timer avoids all HUD creation.
7. The HUD reads current clock direction each update but retains warning latch
   bits. This permits direction changes yet can omit repeated final warnings.
8. Mission+1696 is an owner mask that blocks the standard gauge setter.
   This is a future gauge-hold candidate; direct initialization/setter calls
   bypass it, so a universal gauge freeze remains unproved.
