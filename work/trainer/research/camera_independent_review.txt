Independent camera review — 2026-10-04

Static review only. No game/UI, product, or IDB writes and no build.
Fresh whole-function assembly: 31 functions, 1560 instructions. Every actual
line count equals instruction_count and total_instructions. Evidence is in
camera_independent_evidence_complete.json; the earlier evidence file is a subset.

The roll chain is established by register flow, not inferred from names:
19CBA0 at19CD55 loads Camera+120 in XMM1. 1AADC0 normalizes radians via
1A90C0, supplies XMM1 to141320, then multiplies through13F850.
19D340 has four POINTER arguments, so the existing call is ABI-correct.
It writes eye/target/up and leaves roll unchanged. 19D3D0 takes float roll
in XMM3 as argument4 and leaves up unchanged. The horizontal FOV call is
also correct:19DDE0(projection RCX,radians XMM1,mode0 R8D).

Concrete issue reported to root and camera implementer:
Existing WorldFeatures checks bank0 and AC183C but omits AC1528, the native
camera producer. Owner0 runs normal follow; owner1 runs scripted producer
1780D0; Ti::MGOarashi constructor5423A0 sets owner2. Native follow returns
early when owner is nonzero, while the existing trainer pre-render callback
can still overwrite camera/FOV. Require owner0 for capture and writes,
cancel held-camera lease on takeover, and do not reactivate on owner0 return.
Bind controller mode if the advertised end-on-camera-mode-change is retained.

The old lease compares only scheduler and2world/area bytes. Root was asked
to bind scene heap and all10MapTargetbytes as well, so entrance/spawn changes
and same-room scene replacement invalidate the old held camera.

Numerical requirement:1A90C0 normalizes with repeated addition/subtraction.
Infinity or hugefloat values can prevent progress. Accept only finite,
bounded roll on capture and user change, e.g.-180..180degrees. A later NaN
matrix fallback does not protect against this loop.

Native follow phase is group1,priority26000,callback164860 ->166100.
Recenter flag+65 is consumed and cleared in submode0/165110, then behind-actor
yaw164E90 and distance preset are applied. Snap+64 is consumed and cleared
after mode-specific processing, then164D70 copies smoothing state. Owner!=0
skips both entirely. Queue requests in trainer memory and set them only at
the validated live follow callback, rather than leaving delayed native flags.

Normal disable should drop override flags. Native165700 writes camera,
roll and FOV every ordinary follow frame, so old raw baseline restoration
would be unnecessary and could overwrite a newer native producer state.
