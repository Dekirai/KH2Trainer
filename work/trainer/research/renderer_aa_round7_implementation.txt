Resident MSAA policy implementation
===================================
Status: source, tests, catalog and independent review complete and frozen.
20 fresh full bodies, 2522 instructions and 11939 original PE bytes verified.
9 address-scoped semantic refinements are in the JSON. Export count is not a
claim that every captured subsystem was exhaustively understood.

The installed relay is a 14-byte leaf tail jump. Original113B80 runs exactly
once; its own exception propagates normally. The compiled wrapper then applies
Fixed or Maximum within the fresh native capability/vendor bound. Replay,
history, dirty flags and graphics-resource updates remain in their native paths.
The app-thread native-mutex proof supplies quiescence. An aligned CAS alone does
not make arbitrary concurrent instruction modification safe.

The relay is written RW, changed to RX and flushed before publication. Only the
four-byte aligned call displacement changes. The shared image page needs a short
RWX window because unrelated functions may execute on that page. Captured page
protection is restored before the outer mutex is released. Exposed relays and
the pinned DLL are never freed during the process lifetime, including rollback.

Cleanup refinements from independent review:
- Own Protect/Flush/CAS/query and rollback faults cannot skip the final image
  protection attempt. Uncertain committed CAS still uses owner-only rollback.
- A failed OS restore/flush is reported as permanent failure requiring restart;
  the code does not claim to repair an OS request that continues to fail.
- Host loss disables the mode without a permanent local latch. Changed resident
  object/code/thread identity invalidates it permanently. Both thread creation
  times are checked, avoiding simple handle-value reuse.
- 8AEEF0 is the singleton construction guard seen in11C150, not a demonstrated
  renderer generation. Its equality check is an additional conservative guard.
- A valid new Apply first disables an old mode. Null/invalid arguments reject
  before modifying an existing mode. Disable/Reset never unpatch or force a
  sample count; native adaptation may take several normal frames.

Testing: 2422 checks, 0 failures; /W4 without warnings. Production branch compiled
separately. Tests execute a real RX relay and the real patched E8 displacement in
a synthetic caller, verify all six ABI arguments, and propagate a native error
through the real relay and compiled caller. Synthetic E8 caller has no xdata and
is used only on its normal return path. No copied native body is used to claim
exception-unwind equivalence. All1024 policy combinations and protection/cache/
CAS failures, including errors during cleanup, are checked in isolated memory.
No live game process, window, GPU output, game save or original EXE was touched.

Interfaces: RendererAaHandle, RendererAaCapabilities, RendererAaSnapshot,
RendererAaTick, RendererAaReset and RendererAaFailureReset. Include after
DisplayFeatures. Tick before snapshots; it observes resident identity even when
the mode is disabled. Slots447..455 are exact; actions are not auto profiles.

Remaining boundaries: native graphics/driver failures, uncooperative concurrent
code patchers and externally invented call paths are not proven safe. A static
guard cannot replace a universal renderer-generation API. Limits, authoritative
file hashes and original-byte evidence are in the JSON and checkpoint.
