Native ABI and behavior
Counter: char __fastcall(int value ECX,int index EDX), RVA3FBAE0.
Gauge: char __fastcall(float value XMM0,int index EDX), RVA3FBCB0.
Score: char __fastcall(uintptr_t score RCX,int value EDX), RVA3FA230.
Score points to the native inline object at Mission+1088, fixed ID-1/max9999.
Incidental AL is ignored. Exactly one selected call is made after preflight.
Success acknowledges that the native setter was called, not a universal mission
outcome. No old Actor, Mission, widget or HUD pointer is read after the call.
No retry, undo, save export, artificial item grant or direct value write.

With widget flag4 enabled, counter crossings send14 (zero) or123 (maximum);
gauge sends136/137. Configured widgets require only native initialization flag1.
Flag4 may be clear after hiding; those widgets still accept normal value updates.
Flag0x10 suppresses automatic HUD behavior and does not forbid the setter.
Repeated same-boundary values do not generate an extra crossing event.
Events run global BDX entry10, Actor-controller events, then conditional handlers
synchronously. These may set save/progression flags, award items, end missions,
start presentations or schedule room changes. Native threshold HUD/sound effects
remain active. The native setter may read a new maximum changed by its own event.
Score ID-1 prevents those boundary events; its native threshold behavior still
applies. Setting score preserves repetition history and award coefficients;
later native score-to-EXP/result logic uses the changed number.
Gauge-owner mask Mission+1696 is respected. This does not freeze subsequent
updates. Float precision follows native32-bit float conversion. Maximum must
be <=2147483520, the greatest representable float below signed32-bit overflow,
because native threshold code converts the gauge to int. Large integer maxima
may round to the nearest float; the UI action itself still rejects a double
argument above the current configured integer maximum.

  live current player/status/backlink; no menu/event/title/capture/game-over,

- Live save header KH2J/version58 and writable0x10FC0-byte save are required.

  the active field heap9BA920 as VM allocator2A250A0.39CA10->152590->3E16B0

  allocator is deliberately rejected. The kn::MemoryAllocator vtable/allocate/

  The full cache chain is bounded/acyclic. Event-handler immediate item arrays

Threshold-only actions do not require an idle BDX event context: the checked
threshold callbacks change HUD animation and optionally queue completion audio.
The immediate audio path1DE0C0->1DD510/1DEB50/1DC5B0 has no mission event
dispatch. Its native sound pool and later audio/resource lifetime remain native
engine assumptions; the module does not claim exhaustive audio validation.

Native lifetime and explicit assumptions
Mission widgets occupy reused static storage.3A3460 nulls the global Mission,
queues its script removal and decrements a BAR-cache reference; it does not
immediately free those inline widgets. Mission+16 cleanup is an effect-group
cleanup, separate from allocated counter/gauge HUDs. Global script deletion is
deferred, but Actor action cleanup can flush it synchronously. Event execution
uses temporary BDX contexts with shared-work/Actor references; destruction can
itself execute BDX. The trainer therefore returns without inspecting old data.

Preflight proves immediate structure/entry readiness, not arbitrary external
BDX semantics, every indirect handler/reward dependency, every heap block or
future allocation. Normal loaded game assets and their native lifetime remain
assumptions, as they do for the game's own setters. Arbitrary malformed/modded
scripts, changed deep native hooks, allocation exhaustion or other mods writing
objects concurrently are not guaranteed. Native game faults are not converted
into a claimed successful update by this module. No universal Win/Fail action
or guarantee that a particular counter means mission completion is provided.
