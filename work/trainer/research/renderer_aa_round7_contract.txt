1. The safe point is a conjunction, not the alignment of the write
----------------------------------------------------------------

121D90 calls App.vtable+32 without holding the presentation mutex. The existing
bridge calls the original update once and enters TrainerFrame only afterward.
Reuse display_preview::Ready, its exact object/App/device/root/thread/import
lease, fresh nonzero heartbeat, App+4752<0 and GX+808==0. Acquire the game's
opaque MSVCP mutex at GX+30848, then revalidate the same lease and full pinned
native bodies. Capture lock/unlock addresses before entry and release exactly
once through finally; any uncertain unlock also latches display_preview::faulted.

The only direct caller of113B80 is11A14F. Data references in6A7540/6A7550 are
chained unwind records, not independent callable pointers. Full call topology
and startup/teardown bodies must match before installation. No arbitrary worker
patch or suspend-thread workaround is permitted. Concurrent uncooperative code
patchers cannot be made safe by this contract and are unsupported.

2. Patch and immutable lifetime
-------------------------------
At11A14F the bytes are E8 2C 9A FF FF. Only the naturally aligned DWORD at
11A150 changes, from signed -26068 to a checked rel32 targeting a private relay.
Preserve the E8 opcode and all other bytes. The aligned interlocked CAS provides
atomic data publication; execution quiescence is supplied by section1, and
FlushInstructionCache is separately required before releasing the native mutex.

Allocate one bounded near page within signed-rel32 reach of11A154. It starts
PAGE_READWRITE, receives FF 25 00 00 00 00 followed by the immutable 64-bit
wrapper address, becomes PAGE_EXECUTE_READ, then is flushed. Never use RWX for
the relay. Reject prohibited dynamic code, pin the containing DLL, and verify
the relay range/protection. The relay is a leaf tail jump: no stack adjustment,
nonvolatile modification or extra return address. It needs no dynamic unwind
table. The compiled six-argument C++ wrapper has ordinary PE unwind metadata.

The shared original .text page is different: making it non-executable would
break unrelated functions that other threads can execute on that page. Therefore
use a brief explicitly checked PAGE_EXECUTE_READWRITE window for the image page,
restore its exact original executable/read-only protection and flush. This is
not a claim of universal W^X. Verify MEM_IMAGE, AllocationBase==gameBase, one
committed page and original RX protection before opening this window.

Prepare original function pointer and resident relay before exposure, with
policy disabled. CAS compares only the expected original operand. A changed
opcode/context/operand is rejection, never authority to overwrite another hook.
After any possible publication, retain the relay and pinned DLL until process
exit even if rollback succeeds. On flush/protection/postcheck failure, disable
policy, try CAS rollback only from our own operand to the original, flush, and
restore the saved page protection in finally. If protection restoration fails,
retry it once under the same mutex; do not reopen or repatch on a later command.
A partial failure permanently latches the module. Report the restart-required
condition rather than asserting that a failed OS protection request was repaired.

-----------------------------

4. Disable and lifecycle
------------------------
Disable, Reset, heartbeat loss or a lifetime mismatch clears the policy and last
decision validity. They do not unpatch, destroy the relay, rewrite AA fields or
promise an immediate sample change. Native adaptation resumes at its next normal
decision and can take several frames. No automatic rebind after shutdown/device
or thread replacement: installation owns one validated renderer lifetime.
Transient resize is allowed only while the same lifetime remains valid; max is
read fresh at each policy decision. A capability reduction clamps the policy.
The static-initialization guard at8AEEF0 is only an additional equality check,
not a claimed renderer-generation token. Capture both GetThreadTimes creation
timestamps before/after acquisition and bind them to the resident lifetime;
handle-value reuse alone cannot reactivate it. Host loss is a transient Off,
whereas changed resident identity/code/timestamps latch permanent failure.
All state-changing commands/Tick run on the verified app thread; foreign callers
invoke the immutable original only. FailureReset may atomically clear enabled
state without attempting image or renderer writes.
