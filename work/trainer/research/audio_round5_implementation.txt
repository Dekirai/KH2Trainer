Snapshot meaning
----------------
408 Ready: valid0 when context/host/graph/locks/list are unavailable;1 only after
  full structural list validation and rechecking the captured roots.
409 Registered count;410 allocated capacity;411 historical peak;412 enabled count.
  These can remain valid for an empty list or a temporarily stale selected pointer.
413 Selected ID;414 kind (1Base,2Point,3Line);415 unsigned priority;
416..418 last native audio-update position X/Y/Z.
  All six active fields are withheld together unless selected equals the fully
  validated current winner and the cached position/matrices are finite.

Zero is a valid count, priority or coordinate. Unavailable values have no validity
bit and are not synthesized as zero. The shared frame reset is responsible for
discarding old validity before this module publishes a new sample.

Lifetime and locks
------------------
Only the validated application post-Update continuation may call this snapshot.
It uses the existing audio module's thread, base, disabled and heartbeat gate.
It does not require a loaded Sora scene because the audio graph has its own normal
application lifetime.

Lock order is global Sound CS, then ListenerManager CS+776. Both use TryEnter;
both captured critical-section ranges must also pass Writable because Win32 lock
entry changes their state. Busy means no dependent sample. Captured lock addresses are retained and released
in reverse order through nested finally clauses, including early validation
returns and structured exceptions. IPC publication happens after unlock.

The manager's byte816 is required to equal1, but this is a structural condition,
not a lifetime generation. Native070E20 can leave it1 after deleting the CS.
Normal application init/update/shutdown sequencing supplies the essential
independent lifetime condition. Private teardown by a foreign thread is outside
the observed supported engine path.

The full capacity array is bounded at1024, and all counted pointers and IDs must
be nonnull/nonzero and unique. The module checks exact vtable/BYTEkind pairs and
manager backlinks. Signed count/capacity/peak are bounded before conversion to
lengths. Overflowing pointer ranges are rejected. No pointer read through selected
is performed: only equality with the previously validated winner is used.

Priority selection is uint32 with later-list ties, matching native072070's JA.
Position includes a finite check of its fourth component, plus both cached64-byte
transforms. The unproven field at manager+148 is ignored. A recent setter can
change a listener's own matrix before the next native audio update; the module
reports the manager cache and does not recompute or claim current-frame freshness.
