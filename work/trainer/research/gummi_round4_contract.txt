Native call
RVA21E830, void (__fastcall *)(). No RCX/RDX arguments, no return-status interpretation.
It scans exactly768 records from [base+AF8288], stride176, calls23E020(record), then23DAC0(record) if active.
23E020 reads flags DWORD+128 bit0x100.
23DAC0 clears that bit and calls record vtable slot+48. For exact ENEMY_SHOT vtable base+5B5B70, the slot is base+21F1F0.
21F1F0 writes DWORD([base+AF8278] +16*record.spriteIndex152 +12)=0.
23DAC0 calls a deleting destructor only when record.flags bit1 is set. The proposed preflight rejects that condition.

Semantics and limits
Only ENEMY_SHOT is cleared. ENEMY_LASER and other projectile families use separate pools. Do not silently replace21E830 with broad wrapper1F6050.
No collision callback, item drop, DRAIN absorption point award, HP change or enemy destruction occurs in the verified clear path. Main shot sprite records are cleared; already created impact effects are left to their native visual lifetime.
Enemies can fire again on later frames. This is a single clear, not a no-projectile mode.
The count includes all active ENEMY_SHOT records, including a record in its impact/terminal phase; it is not guaranteed to equal visible flying bullets.
The exact native build and unchanged targeted callbacks are assumed. Checks reject modifications to this pool contract. Future asynchronous game/mod teardown from an unrelated thread is not synchronized by the game's ordinary single-thread scheduler contract.
No live runtime result has been claimed. Synthetic tests should exercise the real preflight implementation with only native callouts replaced.
