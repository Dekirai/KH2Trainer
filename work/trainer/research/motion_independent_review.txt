Concrete source findings sent to author/root
-------------------------------------------
1. CurrentOwner initially accepted unchanged heap/room/Actor identity without
   ScenePhase. Maintain could restore speed after a pending room transition,
   event/title entry or sceneReady loss while stale global identity fields still
   matched. Restore must require a stable current scene, while permitting model
   or ordinary motion changes on the same current Actor.

2. Stop initially cleared observedActor before its scriptChanged/restore check.
   A concurrent WriterHook could read watched0, perform an identical-float native
   write and finish before baseline restoration, so native ownership would be
   overwritten. Checking scriptChanged in Tick alone is insufficient; Root resets
   effects before MotionTick when heartbeat expires. Suggested fix: serialize
   callback observation+original and the Start/Update/Stop mutation sections;
   preserve forwarding on all paths and release the lock during exceptions.
   Native42FCE0 has no recursive callback path in its inspected body.

Required tests after fixes
-------------------------
- Normal motion ID/resource changes keep the actor-wide override.
- Same-value and different-value script writes revoke ownership before nativewrite.
- Same-value script write at expired heartbeat followed directly by Reset/Disable
  does not restore baseline; another Actor's writer does not revoke this lease.
- Concurrent callback vs Enable/slider/Stop has an explicit serial order; no
  loss of native ownership and no stale observedActor clear/reset race.
- Pending room/event/title/unready lifecycle produces no restore to old fields.
- Model/motion data loss on the same stable current Actor may compare-restore.
- Changed Actor, form, status backlink, heap/scheduler/room, external value, table
  or callback slot causes no overwrite of foreign data/hook.
- Slot installation only exact native→own; removal only own→native; already
  dispatched callback still forwards exactly once after removal, bridge pinned.
- Wrong-thread Tick/Reset never writes Actor memory. Readout invalidity publishes
  no stale valid value and field pause remains read-only in snapshots.

Resolution in the frozen final source
-------------------------------------
The callback and Start/UpdateRate/Stop mutations now share an exclusive SRW lock.
The wrapper observes ownership before Original and releases the lock via finally
even when the native callback raises an exception. Baseline capture, observation
publication and initial field write are serialized together. Rate updates check
fresh host, table, owned slot, current Actor and exact written value under lock.

Restore now requires stable ScenePhase and a currently resolved/listed Actor,
plus TableReady/OwnSlot and absence of observed script ownership under lock.
Explicitly unready reset contexts never restore. Hook/bank loss ends the lease
without restoring a value whose writer can no longer be observed, including the
direct Reset and simultaneous HostExpired paths that run before MotionTick.
Model pointer, resource pointer and resource-vtable identity additionally bind
the lease; ordinary Motion/resource/ID changes on the same model remain allowed.
